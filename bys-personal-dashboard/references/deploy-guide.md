# 部署与加桌面指南

第 8-9 步用。

## 第一条规矩：问场景，不问技术方案

**绝对不要**甩一张「EdgeOne / GitHub Pages / Cloudflare / 本地」的对比表给用户。他没有判断依据——他不知道"国内访问不稳定"对自己意味着什么，看到表格只会关掉。

问他打算怎么用，你来翻译：

> 做好了！接下来看你打算怎么用它：
>
> **A.** 先看看效果，好不好用再说
> **B.** 想每天在手机上点开就用（推荐，大概 10 分钟）
> **C.** 手机电脑都要用，换手机也不能丢

- 选 A → 走 **L0**
- 选 B → 走 **L1**（绝大多数人在这）
- 选 C → 走 **L2**，但先把 L1 做完再加

**一次只讲一条路的细节。** 用户主动问"还有别的办法吗"再展开其他的。

---

## L0 · 不部署，直接用

**适合**：想先看看效果、只在电脑上用、或者极度抗拒注册账号的人。

做法：
1. 把整个文件夹打包发给用户
2. 电脑上双击 `index.html` 就能用
3. 想在手机上用：微信发给「文件传输助手」→ 手机上点开 → 右上角「···」→「用其他应用打开」→ 选浏览器

**必须说清楚的两个限制**：

> - 这样打开**加不到手机桌面**（那个功能需要一个网址链接）
> - iOS 上如果 7 天没打开过，Safari 可能会清掉数据——所以记得定期到设置里导出备份

第二条很重要。L0 是唯一有数据丢失风险的方案，因为它享受不到"加到主屏幕"的存储保护。

---

## L1 · 部署上线 + 加到桌面（主推）

**适合**：想每天在手机上用的人，也就是绝大多数用户。

### 为什么推荐这条

- 拿到一个永久 HTTPS 链接，手机上随时打开
- **加到主屏幕后，数据不会被系统清掉**——iOS 对添加到主屏幕的 web app 有独立的存储，不受 Safari「7 天未访问清除」规则约束
- 数据仍然只在用户自己手机里，公网上只有一个空壳界面
- 免费

### 为什么是 EdgeOne Pages 而不是别的

跟用户不用讲这么细，但你要知道：

- **Gitee Pages** 个人版 2024 年已下线，只剩企业版
- **GitHub Pages** 国内时通时断，对一个"每天早上要打开"的东西不合格
- **Vercel / Netlify** 国内访问更差
- **EdgeOne Pages** 腾讯云的，国内节点，有 Pages Drop 拖拽部署，默认域名不需要备案

### 具体步骤（发给用户的版本）

> **上线你的工作台（约 10 分钟）**
>
> 1. 搜「EdgeOne Pages」进腾讯云控制台，微信扫码登录
> 2. 首次使用要**实名认证**——身份证 + 人脸，5 分钟。国内所有云服务都要这一步，绕不开
> 3. 新建项目，选**不需要连 Git 仓库的那种上传方式**（叫「直接上传」「拖拽部署」「Drop」都有可能）
> 4. 把整个 `{{工作台名}}` **文件夹**拖进上传区——注意是文件夹，不是里面的单个文件
> 5. 等十几秒拿到一个 `xxx.edgeone.app` 链接，这就是你的工作台，永久有效

⚠️ **这段步骤没有经过实地验证，是根据公开文档整理的。腾讯云的控制台会改版。**

所以按「入口特征」而不是「按钮名」来指路：用户要找的是**一个不需要绑 Git 仓库、能直接传文件夹的入口**，这个能力不会消失，叫什么名字会变。

**界面跟上面对不上时**（大概率会发生）：

- 让用户**截图给你看**，你按截图上实际有的选项指路。**不要凭记忆猜按钮在哪**，猜错会让用户在控制台里瞎点，比直接说"我看看图"更浪费时间
- 找不到任何上传入口 → 大概率是走到了需要绑 Git 的路径，让用户退回上一步找别的创建方式
- 折腾超过 2 次还没进展 → 按下面「部署卡住时」退回 L0，别耗着

要点提示（这几条比按钮名稳定得多）：
- 上传的文件夹里必须有 `index.html` 作为入口，否则打开是 404
- 系统给的 `xxx.edgeone.app` 域名**不需要备案**；只有绑自己的域名才要备案，别让用户折腾
- 项目名会成为域名的一部分，让用户起个自己记得住的

### 部署后必做：安全提醒

> 提醒一句：这个链接是**公开的**——虽然没人知道，但技术上任何人拿到都能打开。
>
> 不过你的数据是安全的：所有记录都只存在你这台手机里，别人打开链接看到的是一个**空的工作台**，什么都没有。
>
> 所以：链接可以随便发，数据不会跟着走。同样地，**你在别的手机上打开这个链接，也是空的**——数据不跟着链接走，跟着设备走。

最后一句很重要，否则用户换个设备打开发现是空的，会以为坏了。

### 加到手机桌面

**iOS（Safari）**
> 1. 用 **Safari** 打开你的链接（**不能用微信里打开**，微信浏览器没有这个功能）
> 2. 点底部中间的「分享」按钮（方框向上箭头）
> 3. 往下滑，找到「添加到主屏幕」
> 4. 改个名字，点「添加」
> 5. 回到桌面，图标已经在那了 —— 点开是全屏的，看不出是网页

**安卓（Chrome / 各家浏览器）**
> 1. 用浏览器打开链接（同样**不能用微信**）
> 2. 右上角菜单「···」
> 3. 找「添加到主屏幕」或「安装应用」
> 4. 确认

**微信内置浏览器没有这个功能**，这是最高频的卡点。用户在微信里点开链接后要先「用其他应用打开」/「在浏览器中打开」。这句提示要放在最前面。

加完让用户点开确认一次：应该是全屏的、没有地址栏、图标正常。

## L2 · 云端同步（可选升级）

**适合**：明确说了手机电脑都要用、或者"换手机绝对不能丢"的人。

### 先劝一句

L2 不是免费的午餐，动手前先确认用户真的需要：

> 加云同步之前我想确认一下：你是真的会在两台设备上都用，还是只是担心数据丢？
>
> 如果只是怕丢，其实不用这么麻烦——加到桌面之后系统不会清你的数据，再加上定期导出备份，基本就够了。云同步要多注册一个服务、多配几个参数，后面出问题也更难查。
>
> 真的两台设备都要用，那我们就加。

很多人听完会选择不加，这是好结果。

### 真要加的话

架构上已经预留好了：骨架里所有读写都走 `Store`，只需要给 `Store` 换一个 driver，功能代码一行都不用动。

方案是 **腾讯云 CloudBase**（云开发）：静态托管 + 云数据库 + 匿名登录一站式，国内节点，2026 年起每账号每月有免费资源点额度，个人用量基本用不完。

大致流程（具体以当时的控制台为准，做之前先看一眼官方文档）：
1. 开通云开发，创建一个免费环境
2. 建一个集合存用户数据
3. 开启匿名登录（不用做账号系统）
4. 前端引入 CloudBase JS SDK
5. 给 `Store` 加一个 cloud driver：读时先取云端、失败回落本地；写时同时写两边
6. 冲突策略用「最后写入者获胜」——个人单人使用，不需要复杂的合并逻辑

**实施前必须做的事**：先去看当前的官方文档确认免费额度和 SDK 用法，不要凭记忆写。云服务的控制台和额度政策变得很快。

### L2 的额外风险要告知用户

> 加了云同步之后，你的数据会存在腾讯云上（不是在你手机里了）。虽然只有你的账号能访问，但如果你有特别私密的内容（比如日记、树洞），可以考虑让这部分功能**仍然只存本地、不同步**。

这个"部分功能不同步"的设计是合理的，实现上就是在 `Store` 里维护一个本地专属 key 的白名单。

## 部署卡住时

部署是最容易让人放弃的一段。卡住就果断降级，别把人耗在注册流程里。

| 情况 | 怎么办 |
|---|---|
| 卡在实名认证（没身份证 / 不愿意认证） | 立刻降级到 L0。明确告知两条代价：加不到桌面、iOS 上 7 天不打开可能被清数据，所以要定期导出备份 |
| 上传后打开是 404 | 十有八九是拖了单个文件而不是文件夹，或文件夹里没有 `index.html`。让用户重传整个文件夹 |
| 手机上打开白屏 | 让用户在电脑浏览器打开同一链接看控制台报错。国内打开慢通常是引了外部 CDN，回查静态检查的 CDN warn |
| iOS 上找不到「添加到主屏幕」 | 确认他是不是在微信里打开的——微信内置浏览器没有这个功能，必须先「在浏览器中打开」 |
| **任一环节卡超过 2 次** | 停止折腾，退回 L0：先让用户拿到能用的东西。部署随时可以改天再做，热情耗光了就回不来了 |

## 换图标

用户加到桌面后常会说"图标能不能好看点"。按 `build-guide.md` 的图标章节重新生成，替换 `icon.png`，重新上传部署即可。

**注意**：iOS 会缓存图标。换了图标之后，用户需要**把桌面上的旧图标删掉，重新添加一次**，否则看到的还是旧的。这个不说用户会以为没换成功。

## 部署后的收尾

跟用户确认三件事，缺一不可：

1. **手机上打开链接，功能都正常吗？** （电脑上好使不代表手机上好使）
2. **加到桌面了吗？点开是全屏的吗？**
3. **知道去哪备份数据吗？** 带他去设置页点一次导出，让他把备份文件转发到微信文件传输助手存着

第三条一定要真的走一遍，不能只是嘴上说。用户亲手点过一次导出，以后才想得起来。
