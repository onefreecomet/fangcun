# 功能库

第 2 步归纳清单时用，第 6 步实现功能时也回来查。

## 三层分类：这是本 Skill 最重要的概念

同样叫"一个功能"，实现代价差一个数量级。归纳清单时必须给每个功能打上标记，让用户直观看到差异。

| 标记 | 是什么 | 代价 | 会怎么坏 |
|---|---|---|---|
| **〔本地〕** | 状态存在用户手机里的交互功能 | 零门槛，工作台的主体 | 不会坏 |
| **〔内容〕** | AI 一次性生成后写死的知识内容 | 零门槛，但**会过期** | 两三个月后内容用完/过时，需要重新生成 |
| **〔联网〕** | 需要实时外部数据 | **要 API key，可能有 CORS 问题** | 用户不配 key 就是死的；API 关停就废了 |

判断方法：问自己"这个功能在飞行模式下还能用吗"。能 → 本地或内容；不能 → 联网。

### 对用户怎么说

- 〔本地〕：不用解释，直接做
- 〔内容〕：「这部分我一次性生成好放进去，大概够用 X 天，用完了跟我说一声我再生成一批」
- 〔联网〕：「这个需要你自己去 XX 申请一个 key，大概 10 分钟，我会带你弄。不想折腾的话我也可以换成 XX（替代方案）」

**绝对不要把〔联网〕的代价藏到做完之后再说。**

## 通用功能库

每条给出：类型、数据结构、UI 要点、坑。实现时按这个来，别现想。

### 计划与执行类

**📅 今日计划 / 固定行程**〔本地〕
- 数据：`{ date, items: [{time, text, done}] }`，行程模板单独存一份，每天自动生成当天实例
- UI：时间 + 文字 + 勾选框，勾上加删除线并变灰
- 坑：**必须区分"每天重复的固定行程"和"临时加的今日待办"**。用户第二天打开时固定行程要自动重置为未勾选，临时待办要清空。不做这个，用户第二天看到的是昨天勾满的死页面，这个工作台就废了。
- 高频，几乎每个工作台都该有

**✅ 待办清单**〔本地〕
- 数据：`[{id, text, done, createdAt}]`
- UI：输入框 + 回车添加、点击勾选、长按或侧滑删除
- 坑：已完成项要沉底或折叠，否则一周后全是勾

**⏰ 提醒 / 打卡**〔本地〕
- 数据：`{ date: [打卡项] }`，按日期存
- UI：大按钮，点一下就记一次，**不要弹确认框**——打卡的价值就在于零摩擦
- 坑：网页**没有后台推送**，做不到"到点提醒你"。只能做成"打开时看到今天还没打卡"。这一点要跟用户说清楚，别让他以为能收到通知。

**📆 日历**〔本地〕
- UI：月视图网格，今天高亮，有记录的日期加小圆点
- 坑：手机上格子要够大能点，别照搬桌面日历的密度

### 记录与追踪类

**💰 记账**〔本地〕
- 数据：`[{id, date, amount, type: 'in'|'out', category, note}]`
- UI：快速输入（金额 + 分类按钮），下方流水列表，顶部本月收支合计
- 坑：分类按钮要预置好用户自己的分类（访谈时问一句"你主要花钱在哪几块"），不要用通用的"餐饮/交通/购物"
- 进阶：存钱目标进度条（参考案例里有），`{goal, saved}` 两个数就够

**⚖️ 体重 / 身体数据**〔本地〕
- 数据：`[{date, value}]`
- UI：输入框 + 保存，下方最近一条 + 简单折线图
- 折线图别引图表库，用 SVG `<polyline>` 手画二十行就够，避免加载 CDN

**🍚 饮食记录**〔本地〕
- 数据：`[{date, meal, text, photo?}]`
- 坑：**照片存 localStorage 会爆**。localStorage 只有 5-10MB，几张手机原图就满了。必须先用 canvas 压缩到宽度 800px 以内再转 base64，或者只存文字不存图。这个坑不处理，用户存到第二十张照片时整个工作台会崩。

**💧 喝水 / 吃药 / 习惯打卡**〔本地〕
- 数据：`{ date: count }` 或 `{ date: bool }`
- UI：一个大按钮 + 今日次数 + 最近 7 天的小方块热力图
- 极低成本高感知，是最好的推荐项

**📖 读书 / 观影记录**〔本地〕
- 数据：`[{title, progress, note, status}]`

**📝 日记 / 树洞**〔本地 · 敏感〕
- 数据：`[{date, text}]`
- **必须提醒隐私**：这类功能存在时，一定要跟用户确认数据只在本地，并考虑加口令锁
- UI：写完自动保存，别做"保存"按钮——日记这种东西用户写一半切走是常态

### 内容与学习类

**📖 每日单词 / 知识卡**〔内容〕
- 数据：生成一个 N 天的内容数组写死在代码里，按 `今天 - 起始日期` 取模翻页
- 一次生成 30-60 天比较合适。生成 365 天会让文件体积暴涨，AI 后续也难改。
- **必须告诉用户内容会用完**，并说明"用完跟我说，我再生成一批"

**📚 课本 / 教材内容**〔内容〕
- 参考案例里有家长给孩子做的一年级课本内容，这类是典型的一次性生成
- 生成前要问清楚版本（人教版/苏教版）和年级，否则内容对不上

**🧘 养生 / 健身知识**〔内容〕
- 参考案例里的"三伏天祛湿"就是这类
- 注意时效性：跟节气、季节绑定的内容过季就废了，生成时要标注有效期

**🎬 视频 / 教程链接墙**〔内容〕
- 数据：`[{title, desc, url, cover}]`
- UI：卡片网格 + 播放图标（参考案例里的穿搭、健身视频墙）
- 坑：**别嵌入 iframe 播放器**，B站/抖音的嵌入在手机上体验很差且经常失效。做成点击跳转到 App 即可。

### 联网类（谨慎）

**🔥 每日热点 / 新闻**〔联网〕
- 需要新闻 API。**动手前必须先按 `api-guide.md` 的方法实测目标接口的 CORS**——多数国内新闻接口不允许网页直连，测不通就只能走替代方案
- **替代方案**：如果用户不想申请 key，可以做成"跳转到几个热榜网站的快捷入口"，一样解决"我想知道今天发生了什么"的需求，零门槛。**这个替代方案要主动提。**

**🌤 天气**〔联网〕
- 国内的天气 API（和风等）需要注册开发者账号 + 实名，约 15 分钟
- **替代方案**：跳转链接，或者干脆不做——用户手机自带天气，这个功能的边际价值其实很低。**倾向于劝退。**

**🤖 AI 对话 / 陪练**〔联网〕
- 需要大模型 API key。OpenAI 兼容接口的服务大多支持浏览器直连，见 `api-guide.md`
- 这是联网功能里**最值得做**的一个，因为不可替代且价值高
- 坑：流式输出要处理，不然用户以为卡住了

**📤 自动发布 / 自动化**〔基本做不到〕
- 参考案例里出现的"公众号自动发布"多半是演示性的
- 纯静态页面**无法**定时执行、无法后台运行、无法调用需要复杂鉴权的发布接口
- 用户提这类需求时，诚实说明，并引导降级为"一键跳转到发布页 + 内容已经准备好在剪贴板里"

### 固定项

**⚙️ 设置**〔本地 · 必备〕
- 不用问用户要不要，每个工作台都必须有
- 内含：数据备份/恢复、API key 配置、主题切换（如果做了多主题）、清空数据、关于
- 照抄 `assets/skeleton/index.html` 里「功能：设置」分区，没有联网功能就删掉里面的 `apiCard` 卡片

## 高频推荐（主动提，但最多 2 个）

按用户身份挑，**并说明为什么推荐给他**：

| 用户说自己是 | 推荐 |
|---|---|
| 做自媒体 / 博主 | 选题灵感池〔本地〕、发布计划表〔本地〕、每周数据复盘〔本地〕 |
| 上班族 | 待办〔本地〕、喝水提醒〔本地〕、周复盘〔本地〕 |
| 学生 / 备考 | 倒计时〔本地〕、每日单词〔内容〕、番茄钟〔本地〕、错题记录〔本地〕 |
| 家长 | 孩子作业清单〔本地〕、课本内容〔内容〕、成长记录〔本地〕 |
| 减肥 / 健身 | 体重曲线〔本地〕、饮食记录〔本地〕、运动打卡〔本地〕 |
| 自由职业 | 记账〔本地〕、项目进度〔本地〕、时间统计〔本地〕 |

**通用万金油（几乎推荐给谁都合适）**：
- 💧 喝水记录 — 成本极低，感知强
- 📊 每周复盘 — 自动汇总本周的打卡和记账，周日看一眼，能显著提升长期使用率
- 🎯 倒计时 — 有明确目标的人（考试、旅行、纪念日）打开就看到

## 数量与合并

**6-9 个是舒适区。** 少于 5 个单薄，多于 10 个侧边栏在手机上挤到看不清。

超了就建议合并相近的：
- 体重 + 饮食 + 运动 → 「健康」
- 单词 + 课本 + 读书 → 「学习」
- 记账 + 存钱目标 → 「财务」

合并后是一个侧边栏标签，里面放多张卡片。参考案例里的"饮食·打卡"就是合并过的。
